# 知序 · Knowledge Studio

一个可以部署到自己服务器的中文个人学习知识库。通过网页完成资料上传、原文阅读、知识点与技能整理、资料问答、学习计划、练习、复习和设置。

## 已实现

- **资料库**：上传 PDF、Markdown、TXT；按五类用途分类；查看解析状态、失败原因与重试；下载和删除原始资料。
- **阅读与笔记**：资料目录、提取正文、PDF 原文预览、阅读进度；笔记关联来源片段；引用点击定位原文。
- **知识与技能**：编辑、确认草稿、合并知识点；标签、先修关系、掌握自评和复习日期；技能关联知识点、完成标准与实践证据。
- **资料问答**：全部资料或单份资料检索、对话历史、可点击引用、回答保存为笔记；没有依据时明确说明。
- **学习计划**：目标、关联资料、截止日期、可排序步骤与完成进度。
- **练习与复习**：围绕知识点创建回想题或自定义题目、作答、参考笔记、模型反馈或本人自评、复习安排与历史记录。
- **网页设置**：配置兼容 Chat Completions 的模型服务、测试连接、修改访问密码、导出 JSON 学习记录。
- **服务端持久化**：SQLite 数据库与原始文件；访问密码散列、会话登录、API 密钥加密保存。

界面中的统计和学习活动来自实际记录。原创示例资料由用户主动添加，可以随时删除。

## 本地运行

需要 **Node.js 24.x** 与 **pnpm 11.25.0**。可使用 `npm install -g pnpm@11.25.0` 安装 pnpm。

```bash
pnpm install --frozen-lockfile
pnpm dev
```

打开 `http://localhost:5173`。首次进入网页设置访问密码，然后上传自己的资料，或在资料库选择“体验原创示例”。

开发服务器默认仅监听本机。前端为 5173，API 为 3001，由 Vite 代理 `/api`。

生产方式运行：

```bash
pnpm build
pnpm start
```

打开 `http://localhost:3001`。生产服务同时提供网页与 API，不需要单独运行前端开发服务器。

## 部署到服务器

建议使用 Docker Compose；无需在服务器安装 Node.js。

```bash
cp .env.example .env
docker compose up -d --build
docker compose ps
```

默认发布到服务器的 `127.0.0.1:3001`，数据写入名为 `zhixu-data` 的 Docker 卷。容器以普通用户运行，数据卷在升级和重启后保留。

1. 使用 SSH 端口转发，先在自己的浏览器完成首次密码设置：`ssh -L 3001:127.0.0.1:3001 用户@服务器`，再打开 `http://localhost:3001`。
2. 参考 `deploy/nginx.conf` 配置域名代理，使用服务器现有方式配置 HTTPS。
3. 在 `.env` 中设置 `TRUST_PROXY=1`，运行 `docker compose up -d` 使设置生效。
4. 之后从域名进入网页，配置模型并上传资料。

若只在受控局域网直接访问，可在 `.env` 设置 `BIND_ADDRESS=0.0.0.0`，直接访问服务器的 3001 端口；此时保持 `TRUST_PROXY=0`。

部署、备份与排障详见 [部署指南](docs/deployment.md)。当前开发环境没有 Docker，容器构建仍需在安装 Docker 的服务器执行验证。

## 模型连接

网页“空间设置”中填写：

- API 基础地址，例如 `https://你的模型服务/v1`。程序追加 `/chat/completions`。
- 服务商提供的模型名称。
- API 密钥；无需认证的本地服务可以留空。

点击“保存并测试连接”。请求由服务端发出，密钥不会下发到浏览器。上传与阅读、手动整理、练习自评均不依赖模型。

未配置模型时，问答采用**资料摘录模式**，知识点整理采用章节标题与原文提取；页面会清楚标注。配置模型后启用基于资料的回答、知识点生成与作答反馈。

选择云端模型时，相关资料片段、问题、近期对话或本次作答会发送到所配置的服务。Docker 中的 `localhost` 指容器本身；连接其他容器时使用 Compose 服务名，连接宿主机模型时使用可从容器访问的地址。

## 验证

```bash
pnpm test
pnpm build
pnpm exec playwright install chromium
pnpm test:e2e
```

- API 集成测试使用独立临时数据库，覆盖登录、上传、PDF 提取、引用、模型连接、知识点合并、复习、数据导出和重启恢复。
- 模型测试使用本地模拟服务，验证请求格式、引用校验、异常处理和密钥保存。真实服务需在网页中配置并测试。
- 浏览器测试覆盖初始化、阅读与笔记、知识点与技能、计划、问答引用跳转、练习、导出、全局搜索及手机布局。截图保存在 `test-results/`。
- 测试不会向正式资料库添加内容。

## 技术结构

前端为 React + TypeScript + Vite，后端为 Node.js 24 + Express，SQLite 使用 Node 内置驱动。PDF 正文由 PDF.js 提取，检索使用支持中文二元词与英文词项的 BM25 排序。

```text
src/                  网页界面与交互
server/               API、认证、数据库、资料解析、检索与模型调用
tests/                检索与完整 API 测试
scripts/e2e.mjs       浏览器验收
deploy/nginx.conf    反向代理示例
docs/                 产品需求与部署说明
Dockerfile            生产镜像
compose.yaml          单实例部署与持久化数据卷
data/                 本机运行产生的数据（不提交）
```

## 第一版边界

- 当前为**个人单账号空间**。五个资料分类均可使用；团队权限、多成员协作、论文专属对比工作流尚未实现。
- 支持有文字层的 PDF、UTF-8 Markdown/TXT。单份最大 30 MB，每批最多 5 份，PDF 最多 2000 页；扫描件 OCR、EPUB 与音视频待扩展。
- 检索目前是关键词与 BM25，尚未加入向量检索、语义重排或跨文档自动知识图谱。短关键词的结果需核对。
- 每次知识点自动整理使用资料前 24 个片段，最多生成 6 个草稿。其余章节可手动整理，完整分章生成待扩展。
- 练习默认生成概念解释模板，也可自定义题目。复习间隔由当前自评固定为当天、1、3、7 天，不代表客观能力认证。
- 模型调用为普通请求，尚未提供流式输出。单次响应超时为 60 秒，失败时在网页显示错误并保留可重试的输入。
- JSON 导出包含学习数据，不含原始文件与密钥；完整迁移使用服务端数据目录备份。暂未提供 JSON 导入。
- 适合单实例个人使用，尚未进行多用户负载测试。更改默认数据卷名会连接另一份数据，原卷不会自动迁移。
