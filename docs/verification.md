## 2026-11-16：模型推理强度

“空间设置 → 模型连接”新增推理强度下拉框，所有者 / 管理员可修改；编辑者和只读成员不能写入设置。配置通过 C++ 保存到原有 config 表，无需数据库迁移。旧数据库默认 `default`，旧客户端省略新字段时保留已保存值；显式 `default` 清除请求中的强度参数。

通过本地 HTTP 模拟服务捕获实际 C++ 请求：七个显式档位正确发送 `reasoning_effort`、省略 `temperature`，连接测试与正式问答使用对应的 token 上限；论文对比和 Wiki 生成同样采用空间配置。仅明确拒绝 `max_completion_tokens` 的 400 / 422 响应会触发一次参数兼容重试，选定的强度、消息和预算保持一致。无效强度、鉴权失败、上游 503、token 预算错误均不触发降级；无正文回答被拒绝，失败不写入对话，不暴露上游错误细节或思考内容。

新增 API 回归覆盖配置校验、非法配置原子性、重启持久化、旧客户端、兼容重试次数、失败后的对话与配置。新增网页回归通过真实设置表单与模拟模型验证选择、保存、连接测试、错误提示、刷新与恢复服务商默认；移动端只读成员的下拉框不可修改，页面无横向溢出。截图保存在忽略的 `test-results/model-reasoning-settings.png` 与 `test-results/model-reasoning-mobile-readonly.png`。

模型请求验证使用隔离临时数据库和本地模拟服务，未使用真实提供商密钥。

## 2026-11-16：任务状态保存时序修复

GitHub Actions 的团队网页验收在连续切换任务状态时超时。原看板保存后触发全局异步刷新，却在新状态和版本号加载前解除禁用，下一次提交可能携带旧版本；刷新还会暂时卸载看板。通过阻塞任务列表响应，已在原实现上稳定复现列切换超时。

修复后，看板直接采用 C++ PATCH 接口返回的状态和版本号，再允许该任务继续操作；旧列表响应不能覆盖已确认的新版本。保存中的任务分别锁定，失败后保留原状态并允许重试。

新增浏览器回归使用响应门闩和虚拟时钟控制任务轮询，不增加固定等待或放宽超时：检查保存中禁止重复提交、连续推进携带正确版本、503 失败后重试、迟到旧列表不回退状态，以及重新加载后的持久化和负责人显示。`pnpm build`、11 组 `pnpm test`、18 组 `pnpm test:e2e` 全部通过。远端 Ubuntu / Docker 验证以本次推送触发的 Actions 结果为准。

虚拟时钟仅用于任务回归，论文审核使用正常时钟。发布阻断同时断言真实 HTTP 409、接口错误内容和网页提示；验收失败时记录接口错误并截图各浏览器身份，方便定位 Linux 环境差异。

弹窗初始焦点改为布局阶段同步设置，初始化及关闭恢复焦点均禁止自动滚动，移除 40ms 延迟回调与快速编辑之间的竞争。Wiki 验收检查初始焦点和正文预览模式，并在失败时保存编辑器状态和截图。任务测试在团队页面标题出现后才开始控制轮询，避免误匹配导航前论文页面上的关联任务。

## 部署边界

- 本机无 Docker，尚未在本机构建 / 启动容器。提供 C++ 多阶段 Dockerfile、Compose、健康检查、Nginx、备份和恢复文档。
- 提供 GitHub Actions：Ubuntu 原生编译、API / 浏览器测试、Debian 生产镜像构建与容器健康接口检查。工作流配置本身不代表远端已经通过，以 Actions 结果为准。
- 模型使用本地模拟服务，没有真实提供商凭据；真实服务需在网页配置并测试连接。
- 未连接用户服务器、域名或证书，未进行远程部署。
- 未做大规模压力测试、多租户隔离或按文档访问控制。本版本明确是一套部署一个共享团队。
