## 2026-11-16：任务状态保存时序修复

GitHub Actions 的团队网页验收在连续切换任务状态时超时。原看板保存后触发全局异步刷新，却在新状态和版本号加载前解除禁用，下一次提交可能携带旧版本；刷新还会暂时卸载看板。通过阻塞任务列表响应，已在原实现上稳定复现列切换超时。

修复后，看板直接采用 C++ PATCH 接口返回的状态和版本号，再允许该任务继续操作；旧列表响应不能覆盖已确认的新版本。保存中的任务分别锁定，失败后保留原状态并允许重试。

新增浏览器回归使用响应门闩和虚拟时钟控制任务轮询，不增加固定等待或放宽超时：检查保存中禁止重复提交、连续推进携带正确版本、503 失败后重试、迟到旧列表不回退状态，以及重新加载后的持久化和负责人显示。`pnpm build`、11 组 `pnpm test`、18 组 `pnpm test:e2e` 全部通过。远端 Ubuntu / Docker 验证以本次推送触发的 Actions 结果为准。

## 自动化覆盖

1. C++ 中文 / 英文 BM25 检索、无相关结果、重叠切片与尾部完整性、Markdown、跨 UTC 午夜的上海日期、scrypt 校验。
2. 原学习 API 全流程：认证、Origin / Cookie、资料、笔记、知识点、循环检测、技能、计划、引用问答、练习与复习、导出与重启持久化。
3. PDF：英文、依赖 CMap 的中文、损坏文件、解析重试和原始文件读取。
4. 模型：本地模拟 Chat Completions、Bearer 密钥、模型错误不写入对话、无效引用过滤、数据库中无明文密钥。
5. 旧数据升级：用 Node 旧格式生成数据库和 AES-GCM 密钥，C++ 升级后原密码、正文、笔记与模型密钥继续使用；生成备份；重启幂等；维护命令重置所有者并撤销会话。
6. 团队：邀请预览、单次使用、撤销、角色限制、只读写入拒绝、管理员边界、密码重置、会话撤销、停用与所有权转移。
7. 协作：评论作者权限、解决状态、任务分配、负责人推进、任务删除限制、操作归属；两成员同时保存同一笔记，只有一个成功，另一个返回 409。
8. 论文：唯一档案、元信息、资料删除保护、矩阵真实证据归属校验、服务器替换伪造引文、草稿生成、内容冻结、审核人权限、未解决评论阻断、发布、历史恢复、Markdown / JSON 导出和重启。
9. 论文模型生成：每篇批量归纳、上游失败不改变版本；模拟慢模型期间另一成员保存，生成结果返回 409，不覆盖同事更改。
10. Wiki：多来源草稿范围和未落库提案、证据归属校验、伪造引文替换、发布引用编号与未解决讨论门槛、已发布内容锁定、并发版本、反向链接、来源删除保护、历史快照 / 恢复、Markdown 和完整 JSON 导出、重启持久化。
11. Wiki 检索：用只存在于知识页标题中的别名找到原文，未发布草稿不参与引导；固定资料范围隔离；原文重复片段去重和其他来源覆盖；知识页 ID / 标题 / 版本线索持久化；只读成员读取权限和写入拒绝。
12. Wiki 模型：一次多来源请求、每份至多 4 个片段、包含首尾位置、上游失败 / 虚构引用不落库；生成之后原文被删除时保存回滚。
13. 指纹与 v2 升级：改名后的重复文件拒绝、批量回滚、相同资料并发上传只写入一次、v2 数据库自动备份和指纹回填、原正文 / 密钥保留、迁移幂等和历史重复提示。

## 部署边界

- 本机无 Docker，尚未在本机构建 / 启动容器。提供 C++ 多阶段 Dockerfile、Compose、健康检查、Nginx、备份和恢复文档。
- 提供 GitHub Actions：Ubuntu 原生编译、API / 浏览器测试、Debian 生产镜像构建与容器健康接口检查。工作流配置本身不代表远端已经通过，以 Actions 结果为准。
- 模型使用本地模拟服务，没有真实提供商凭据；真实服务需在网页配置并测试连接。
- 未连接用户服务器、域名或证书，未进行远程部署。
- 未做大规模压力测试、多租户隔离或按文档访问控制。本版本明确是一套部署一个共享团队。
