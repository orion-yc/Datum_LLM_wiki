# C++ 服务器部署与维护

## 服务结构与参数

浏览器 → HTTPS / Nginx → `datum-server` C++20 → SQLite / 上传文件 / Poppler。使用 Qt Core、Network、Sql 和 Gui（图片头校验），OpenSSL 和 cpp-httplib；网页来自 React 构建产物。运行环境不依赖 Node.js。Linux 上 WebP 预览需安装 Qt 图片格式插件。

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `BIND_ADDRESS` | `127.0.0.1` | Compose 宿主机监听地址 |
| `PORT` | `3001` | 宿主机映射端口；原生启动时为监听端口 |
| `DATA_VOLUME` | `zhixu-data` | 升级时保留原数据卷名称 |
| `TRUST_PROXY` | `0` | 唯一入口为可信反向代理时设为 `1` |
| `APP_TIMEZONE` | `Asia/Shanghai` | 复习日历时区 |
| `HOST` | `0.0.0.0` | 原生监听地址 |
| `DATA_DIR` | `./data` | 容器内为 `/app/data` |
| `STATIC_DIR` | `./dist` | 容器内为 `/app/dist` |
| `PDFTOTEXT` | `pdftotext` | Poppler 程序路径；不拼接 shell |
| `PDFINFO` | 自动发现 | AI 解析页数工具；优先使用 `PDFTOTEXT` 同目录程序，否则使用 PATH |
| `PDFTOPPM` | 自动发现 | AI 解析逐页渲染工具；可指定绝对路径 |

`.env` 由 Compose 读取，原生运行需自行设置环境。

## 首次部署

```bash
cp .env.example .env
docker compose up -d --build
docker compose ps
docker compose logs --tail=80 app
```

默认仅本机能访问 3001。先用 SSH 隧道创建所有者账号、显示姓名、空间名和密码，再配置 HTTPS。无默认密码。团队页面生成单次邀请，受邀者自行设置独立密码。

修改 `deploy/nginx.conf` 的域名、证书和上游端口。模板允许 160 MB 请求，网页每份最多 250 MB、每批 5 份。超过 30 MB 的文件或总大小超过 32 MB 的批次走 `/api/uploads` 分块接口，网页新请求每块 1–4 MB 自适应（服务端兼容旧客户端最多 8 MB），临时分块在 `data/upload-staging/` 落盘；完成后流式校验指纹并整批导入。原 `/api/sources/upload` 保留每份 30 MB 的兼容限制。无需提高 Cloudflare 的 100 MB 单次请求限制。未完成上传有效期为一小时，后续新建上传时清理过期文件；每成员最多两个、全站最多八个未完成任务。论文生成最多逐篇调用 8 次模型，每次默认最长 60 秒，显式推理强度时最长 180 秒；按实际模型速度调整代理读取超时。普通 PDF 解析最长 120 秒。AI PDF 解析通过后台队列逐页执行，不占用长时间的网页请求。

可信代理为唯一入口时设置 `TRUST_PROXY=1`，传入 `X-Forwarded-Proto: https` 后 Cookie 附带 Secure。代理保留 Host，应用检验写请求 Origin。

容器以 UID / GID 1000 的 `datum` 运行，沿用旧镜像 UID。运行容器只读，数据库、密钥和文件写入挂载卷。

## 旧版升级与回退

1. 停止旧服务并完整备份。
2. 更新代码，保留 `.env`、`DATA_VOLUME` 和挂载位置。
3. 执行 `docker compose up -d --build`。
4. 用 **admin** 与旧访问密码登录，核对资料和模型设置。

首次迁移在 `data/backups/` 建立 `before-cpp-*.sqlite` 和配对 `.key`；迁移在事务内执行，重启不重复。原始文件不移动，旧会话失效，密码散列和 AES-GCM 格式兼容。

从 v0.2 C++ 版本升级到 v0.3 时同样备份；已有成员与会话保留，模式升到 3，增加 Wiki 页面、证据、链接和历史表，并为旧上传文件补建内容指纹。备份沿用上述文件名前缀。指纹回填期间启动可能稍慢，不会调用模型或修改原文内容。

本次 AI PDF 功能将模式从 3 升到 4，先备份再增加任务、页面及片段版本字段。AI 结果只有网页核对采用后才更新当前页面；历史片段继续支撑已有引用。整本任务将模式升级到 5，保存可续跑标志和逐页采用状态。新任务重启后恢复排队，跳过已持久保存的页面；旧任务仍标为中断，不在升级时自动调用模型。暂停跨重启保留；失败任务可继续未完成页。上游已计费但结果尚未保存时崩溃，重试该页仍可能再次计费。

互联网学习使用数据库模式 8，包含项目、版本、索引、学习记录及关联表。服务器用 `api.github.com` 获取清单；有多个未缓存文件时，优先从 `codeload.github.com` 下载固定提交的 ZIP（临时磁盘上限 128 MiB），再从 `raw.githubusercontent.com` 补齐。归档不会解压到目录，只有与已知 Git blob 匹配的内容才入库。公开导入不依赖浏览器上传。后台串行执行，每个范围最多列出 20,000 个文件，候选正文总量 256 MiB，单文件最多 2 MiB；逐文件提交进度，暂停和重启可以续跑。GitHub 公共 API 限流或返回截断清单时，页面会显示失败原因。

编辑者可以删除项目，取消正在运行的导入，并清理该项目的版本、学习记录、导读和源码关联。GitHub 原仓库、Wiki、知识点、学习计划和其他项目共享的正文不会删除。

回退时停止 C++ 服务，恢复完整升级前备份，再启动旧镜像。不要让两个版本同时访问同一目录，不要用会删除数据卷的 `docker compose down -v` 更新。

## 备份与恢复

管理员网页 JSON 导出包含学习记录、Wiki 页面和关系、论文、版本、讨论、任务和成员公开信息，不含密码、会话、邀请令牌、模型密钥或原始文件。

完整恢复需保留整个目录：

```bash
docker compose stop app
docker compose cp app:/app/data ./datum-data-backup
docker compose start app
```

每次使用新的备份名。包括数据库及 WAL / SHM、`uploads/`、`pdf-previews/`、`.encryption-key`、`backups/`。没有原密钥无法解密原模型密钥。`pdf-previews/` 保存每份 PDF 最近一次解析的页面图片，便于电脑和手机直接对照；下一次解析会清理旧图片，删除资料时同时删除缓存，不影响原始 PDF 和历史文本引用。

恢复到已创建数据卷：

```bash
docker compose create app
docker compose cp ./datum-data-backup/. app:/app/data
docker compose run --rm --user root app chown -R datum:datum /app/data
docker compose up -d
```

## 密码恢复

普通成员由管理员在网页重置。所有者遗失密码且无人可管理时，在服务器终端恢复；新密码从标准输入读取，不进入命令行参数。先备份。

```bash
docker compose stop app
read -s -r -p 'New owner password: ' DATUM_NEW_PASSWORD
printf '\n'
printf '%s\n' "$DATUM_NEW_PASSWORD" | docker compose run --rm -T app /app/datum-server --reset-owner-password
unset DATUM_NEW_PASSWORD
docker compose up -d
```

此命令重置当前所有者密码并撤销全部会话，保留资料。不要删除用户表或数据库重置密码。

## 排查

- **资料为空**：核对卷名、数据目录和挂载位置，可能连接了新目录。
- **PDF 失败**：检查扫描件、密码保护或损坏；原生运行需确保 `pdftotext`、`poppler-data` 可用。扫描页可使用阅读页的 AI 解析；需 `pdfinfo`、`pdftoppm` 和支持图片输入的模型，普通文本连接测试成功不代表模型具备视觉能力。
- **AI PDF 未完成**：在阅读页查看进度与错误，缩小页面范围检查服务商的图片输入和输出预算限制。可一次选择整份或长范围（AI 最多 10,000 页），结果每批 50 页核对采用；全实例视觉请求串行运行，新任务每 5 页轮转，最多排队 12 个任务。暂停或取消会尽力中止当前请求，未保存的当前页在继续时重新处理。关闭浏览器不会取消后台任务，新任务重启后自动续跑。模型失败不会覆盖已采用正文。
- **模型失败**：地址包含 `/v1` 等服务前缀，不包含 `/chat/completions`；核对模型 ID、密钥、额度和网络。容器内连接宿主机模型需使用容器可达地址。
- **版本冲突**：保留需要的输入，读取最新版本再合并。旧版本保存不会覆盖新内容。
- **发布拒绝**：检查指定审核人、每格证据、综合结论、未解决评论及工作流状态。
- **Wiki 发布拒绝**：补充正文和原文证据，修正 `[n]` 编号，解决关联讨论。已发布页面需由管理员转回草稿后编辑。
- **重复上传**：内容指纹与已有文件一致时本批次整体不导入，请在资料库查找已有资料；解析失败可使用原条目的重试入口。

本机完成 Windows 原生 C++ 编译运行验收。Docker 本机不可用；服务器首次部署需验证镜像构建、健康检查、数据卷持久化与 HTTPS。

低内存服务器建议在有足够内存的构建机生成产物或镜像后再部署，避免同时运行 C++ 优化编译、前端类型检查和现有服务。AI 解析本身逐页渲染、串行请求，无需在服务器加载模型或 OCR 框架；仍应从少量页面开始观察实际内存和耗时。


## 增量解析与核查（模式 7）

模式 6 / 7 增加页面核查、草稿版本、复用来源和显式重新解析标志字段。升级前保留完整数据目录；历史采用状态保留，新建整份 / 连续范围任务默认复用同一资料此前成功的页面，包括未采用的草稿和校对。显式重新解析才再次调用模型，旧正文在新结果采用前保持原样。来源模型不同会在核查界面显示，复用行为不依赖模型相同。

核查草稿按页保存且携带版本，过期保存返回 409。范围核查只标记该范围内已经完成且未采用的页。一次采用全部已核查页面由浏览器自动分批调用，每批事务最多 50 页，前序成功批次不因后续失败回滚；网页给出成功计数，刷新后重试只包括剩余页。结果正文分页返回，核查索引只包含页码和版本，不加载全书正文。

同页长正文仍保留多个检索片段，阅读目录按物理页码去重；目录中“已整理”页数仅统计已有正文的页面。


## 上传超时恢复

新上传任务从 1 MiB 分块开始，稳定快速响应时加倍到最多 4 MiB；分块耗时超过 8 秒缩小，临时错误后退回 1 MiB 重试。网页显示速度和估计剩余时间，减少快速线路中的请求往返。`GET /api/uploads/:id` 验证成员归属后返回各文件的已保存字节数。重复 PUT 仅在已有相同位置的字节完全一致时确认成功，异内容返回 409。前端对网络错误、408 / 429 / 常见临时 5xx 最多重试三次，间隔 1 / 2 / 4 秒；失败保留分块，当前文件选择不变时再次上传从服务端偏移继续。任务过期后需重新创建，浏览器刷新后的自动恢复尚不支持。

本次故障日志为 Caddy 对 8 MiB 上传块写入后端超时，返回 504；非文件大小或模型配置错误。网页对非 JSON 代理错误展示 HTTP 状态，避免吞掉故障原因。Caddy 和 Cloudflare 配置无需修改。
