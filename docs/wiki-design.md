## 本项目中的落地

### 资料层、Wiki 层、学习层

- 资料层：上传文件与解析片段，保留页码或片段位置，是引用依据。
- Wiki 层：跨资料的概念、方法与实践、主题综述；具有摘要、标签、正文、证据、关联页、反向链接和版本。
- 学习层：现有知识点、先修关系、技能、练习、熟练度和学习计划继续使用，处理个人理解与实践进度。

一套部署仍对应一个共享团队。Wiki 草稿对团队成员可见；只读成员可阅读、搜索、看历史、导出 Markdown，不能写入。草稿不参与辅助问答检索。

### 先提出草稿，再保存与发布

“从资料整理”可选择 1–8 份已解析资料。C++ 为每份资料选择至多 4 个片段，保留首尾位置，再结合主题相关候选和分布位置补充；最多 32 个片段，每个进入模型的正文最多 1100 字。网页显示每份资料的已用 / 总片段数，避免把局部资料归纳误称为全书结论。

配置模型时用一次请求生成严格 JSON；未配置时返回明确标注的原文摘录草稿。生成接口不写数据库。用户可以改写摘要、正文、标签、类型、方向，手动补充其他原文证据，再保存。

保存证据时只信任片段 ID，服务端重新读取原始内容和归属；客户端引文不能替换原文。发布要求非空正文、至少一条有效证据、正文存在合法 `[n]` 引用、无未解决讨论。这里检查的是引用格式和关联完整性，语义是否准确仍由发布成员核对。

发布后正文锁定，管理员可转回草稿。每次保存、状态改变、历史恢复都写入不可覆盖的快照；恢复创建新的草稿版本。历史中已不存在的资料或关联页会阻止恢复，避免保存悬空引用。所有更新、发布和恢复必须携带版本号，冲突返回 409。

### 关联、反向链接与质量检查

关联关系使用稳定页面 ID，由独立关系表保存。反向链接直接查询关系表。关联页和来源片段受数据库外键保护；删除被其他知识页关联的页面、删除仍被 Wiki 引用的资料会被拒绝，需先解除关联。

“质量检查”由本地确定性规则计算，不调用模型，也不自动改写内容：

- 已解析但未整理到 Wiki 的资料。
- 无原文证据、空正文、引用编号缺失或越界。
- 待整理草稿、没有反向链接的非综述页面。
- Unicode 规范化及去空白后的同名页面。
- 解析失败、历史完全重复文件、损坏的页面关联、未解决讨论。

每条结果都有实际页面或“从该资料整理”的入口。孤立页和同名页是提示，不代表一定错误。本版没有自动检测语义矛盾，也没有自动合并或删除页面。

### 问答检索

现有中文二字词 / 英文词 BM25 原文检索保留；额外检索已发布 Wiki 的标题、标签、摘要和正文，再沿证据关系找到原文。以倒数排名融合组合两路候选：原文权重 1，Wiki 权重 0.8，排名常数 60。该算法是本项目的实现，没有将 Dify 的向量分数当成本项目已有能力。

候选按片段 ID 和规范化正文去重。第一轮每份资料最多取 2 个片段，第二轮补足剩余名额，减轻单一资料占满答案的问题。所有 Wiki 引导片段都必须存在于当前对话允许的原文范围内。

模型最终收到的是原文，Wiki 本身不冒充原始证据。每条引用保存本次所用知识页 ID、标题和版本，网页可显示“经由知识 Wiki 定位原文”。知识页后来被编辑或删除，旧对话的引用和检索线索仍保留当时快照。

此版没有 embedding、向量数据库或神经网络重排。没有词面匹配且未被 Wiki 组织起来的语义关联仍可能漏检。不能据此声称达到大规模向量检索效果；当前检索会扫描本地片段，适合先验证中小规模知识库。

### 重复资料与存储

上传使用文件字节的 SHA-256 指纹，独立于文件名。批量中遇到重复文件返回 409 并回滚本批新增文件；并发上传相同内容只写入一次。相同内容使用不同编码或换行时指纹可能不同，本版不做模糊文件去重。

SQLite 模式升到 3；旧数据库升级前备份数据库与加密密钥；v0.2 原账号、资料和学习记录保留，为可读取的旧上传文件补建指纹，不自动删除历史重复资料。已有数据目录不能被清空来“完成迁移”。

主存储使用 SQLite 事务维护页面、关系和历史，避免同时维护数据库和 Markdown 文件产生双份状态。单页可导出 Markdown；管理员完整 JSON 导出包含 Wiki 页面、证据关系、链接和快照。原始文件和密钥需完整备份 `data/`。

## 网页路径与接口

网页目录为 `/#/wiki`，知识页为 `/#/wiki/<id>`，资料阅读页提供“整理到 Wiki”入口。无需终端操作知识内容。

| 接口 | 用途 |
| --- | --- |
| `GET /api/wiki`、`GET /api/wiki?q=…` | 全部页面 / 检索目录 |
| `POST /api/wiki/draft` | 从资料产生未保存提案 |
| `POST /api/wiki`、`PUT /api/wiki/:id` | 创建 / 保存草稿 |
| `GET /api/wiki/:id` | 页面、原文证据、关联与反向链接 |
| `POST /api/wiki/:id/state` | 核对发布 / 管理员转为草稿 |
| `GET /api/wiki/:id/history`、`POST /api/wiki/:id/restore` | 快照与恢复 |
| `GET /api/wiki/:id/export` | Markdown 报告 |
| `GET /api/wiki/audit` | 质量检查 |
| `DELETE /api/wiki/:id` | 受引用关系保护的删除 |

评论和任务复用既有 `/api/comments`、`/api/tasks`，对象种类为 `wiki`。完整验证见 [verification.md](verification.md)。
