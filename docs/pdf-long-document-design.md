# 长篇 PDF 后台解析设计

状态：核心整本任务功能正在实施，本文包含后续规划，不能将全部条目视为已实现。日期：2026-11-16。

目标：用户为一本几千页的教材启动一次任务后，可以离开网页；服务逐页处理并保存结果，中断后继续，用户按批核对和采用。适配当前约 1.6 GiB、无 swap 的服务器，继续使用 250 MiB 文件限制和 8 MiB 分块上传。

## 本次实现范围

已实现整份 / 连续范围的一次启动、暂停、继续、成功页跳过、重启恢复、每 5 页调度让出、50 页结果分页和完成页分批采用。上传和阅读页使用同一任务机制，250 MiB 分块上传保留。AI 页数边界为 10,000；普通正文提取仍保留 2,000 页 / 40 MiB 输出保护，活动片段仍受 15,000 条容量保护。页面预览缓存约 512 MiB，缺失时本地重新渲染。

2026-11-17 补充实现跨任务增量复用、校对草稿保存、逐页核查与版本校验、范围核查及一次采用全部已核查页（内部小批事务），目录按物理页归并。下文的多段解析范围、自动试读暂停、金额 / token 预算、按页自动重试与跳过坏页、不同页采用的完整独立版本控制、普通提取 / 阅读 / 检索全面分页改造仍是后续规划。本次失败会暂停为失败状态，用户可继续缺页；并未自动判断哪些页面质量较差。

## 1. 用户流程

### 上传和阅读页使用相同的解析选项

上传默认普通解析。打开“AI 版面解析”后选择范围：

| 选项 | 行为 |
| --- | --- |
| 先试读 | 默认取前 5 页，可修改；适合检查模型效果 |
| 整份 PDF | 后台读取真实页数，覆盖整份文档，只需启动一次 |
| 指定范围 | 如 `1-30, 85-120, 400`，合并重复页并校验范围 |

阅读页另外提供“继续未完成页面”和“仅重试失败页”。它们继续原任务，保留模型、提示词版本和已完成页，不重新收费解析已有成功结果。重做已成功页面是独立的显式操作，标明会再次调用模型。

在开始前显示文件名、真实页数、范围、预计调用量和模型；未知页数时先完成轻量文档检查，不创建未经确认的整本模型任务。必须能区分 PDF 物理页码与书籍印刷页码，输入和进度统一使用物理页码。

超过 50 页且该模型尚未在此任务试读时，默认先处理 5 页并暂停供用户看效果。用户可以在同一个开始表单中选择“直接连续解析整份”，不强制反复确认。试读通过后点“继续剩余页面”一次即可完成整本排队。

### 独立任务页面

将长任务放进资料阅读页可进入的“解析任务”页面，保留现有弹窗作为快捷入口。任务页至少展示：

```text
Primer C++ 第 5 版 · 共 1,240 页
AI 已成功 350 页 / 待处理 887 页 / 失败 3 页
已核对 100 页 · 已采用 100 页
当前处理：第 354 页 · 按最近处理速度估计剩余时间

[暂停解析] [查看待核对结果] [仅重试失败页]
```

页数仅为示例。进度按真实页状态汇总，重试次数不算完成页。成功进度与“已尝试处理”分开展示；有失败时不能显示为“全部成功”。样本不足时显示“正在估算”，不能承诺固定完成时间。

允许关闭网页、切换资料和退出登录；后台任务不绑定浏览器会话。任务列表可以跨文档查看进度。只读成员能查看结果，编辑者可创建和核对任务，管理员可管理全空间任务与预算；执行操作沿用现有共享团队权限。

### 控制语义

| 操作 | 行为 |
| --- | --- |
| 暂停 | 停止领取下一页；当前页完成并落盘后暂停，页面标明“暂停中” |
| 继续 | 从未完成页继续，跳过成功、空白和已采用页面 |
| 仅重试失败页 | 只重置可重试的失败页；不改变其他页 |
| 停止任务 | 尽快取消当前上游请求并停止调度，保留已完成结果供查看、采用或以后继续 |
| 删除草稿 | 独立操作，仅删除未采用结果；明确显示涉及页数 |

暂停、继续、采用、重试必须可以重复提交而不重复执行。读取结果不得自动开始模型调用。任务创建者被停用或失去编辑权限时暂停其未完成任务，由管理员接管后继续。

## 2. 长文档的核对与采用

50 页调整为默认核对分组大小，后台不因此自动暂停。允许选择每组 20 / 50 / 100 页；失败页单独标记，可先核对成功页。

页面列表分页显示，筛选“未核对、失败、有警告、已采用”；只请求当前页正文和预览。支持跳转页码、上一页 / 下一页、编辑草稿、逐页标记已核对，以及“采用本组已核对页面”。无需等待整本解析完成，也不会声称几千页均已核对。

采用规则：

- 默认只采用用户明确标记已核对的页面；不提供默认自动采用 AI 结果。
- 每次只提交页面 ID、修订号和采用操作，正文编辑通过独立接口保存，避免一次提交全书正文。
- 每个采用事务最多 50 页；前端可一次选择更多，后台拆成多个事务并逐批汇报。任何一批失败，明确展示已完成批次，不能宣称全操作回滚。
- 同页草稿或现有正文版本变化时返回 409，不覆盖其他人的核对；不同页的采用不相互阻断。
- 采用成功后的历史片段保持不可变，笔记、Wiki、论文证据继续引用原片段；活动正文按页切换到新版本。
- 未采用页继续使用已有普通正文；扫描页尚无可用正文时明确显示未解析。
- 空白页显示“识别为空白”，需核对后才能取代该页已有正文；空白页不生成虚构文本。

编辑校对草稿保存在服务端，带修订号；切换页面、关闭网页或重启不丢失。浏览器切页时提示未保存输入，后台轮询不能覆盖正在编辑的内容。

## 3. 持久任务模型

保留 SQLite 和 C++ 后台工作线程，首期不引入外部消息队列。一个文档任务包含逐页工作项；核对分组是视图，不是另建几十个独立任务。

| 记录 | 关键字段 |
| --- | --- |
| 文档任务 | source_id、文件指纹、范围、模型 / 服务地址 / 提示词配置快照、创建者、调度状态、暂停原因、预算、时间戳 |
| 页面工作项 | job_id、物理页码、状态、尝试次数、重试时间、租约、输入 / 配置指纹、错误类型、用量 |
| 页面结果版本 | page_item_id、原始模型结果、编辑后正文、警告、空白标记、结果版本、核对者 / 核对时间 |
| 采用记录 | 页码、被采用的结果版本、采用者、当前正文版本、幂等操作 ID |
| 文档页索引 | 页数、页级普通文本状态、活动正文版本；与是否做过 AI 解析分离 |

页面工作状态：`pending → running → succeeded / blank / failed / skipped`。任务调度状态：`queued / running / pause_requested / paused / completed / stopped`；任务另有汇总 `completed_with_errors` 与核对计数，不能用一个 `ready` 状态同时表示传输、解析、核对和采用。

事务中领取单页、设置持久租约；单工作线程也使用同一机制，便于异常恢复。每页的结果和状态在同一事务提交，计数从页状态汇总或事务内更新。唯一约束 `(job_id, page)` 防止重复页。

重启时恢复原本允许运行的任务，回收过期的 `running` 租约并重新排队；用户暂停、预算暂停、凭据错误暂停和已停止任务保持原状态。成功页和核对结果继续保留。沿用任务原配置，不静默切换到空间刚修改的其他模型；密钥只保存引用，不复制明文，密钥失效时暂停等待更新。

对仍在运行的相同文件、范围和配置的重复创建请求返回已有任务。历史成功结果只在同一文件与配置版本且未要求重新解析时复用。更换模型、提示词或渲染配置后必须明确创建新结果版本。

**费用的保证边界：** 本地完成事务后不重复调度成功页面。若上游已计费但结果尚未保存时进程崩溃，重新请求仍可能再次计费；本地幂等不能保证上游账单只计一次。服务商支持幂等键时可接入，否则展示这种异常重试的记录和用量不确定性。

## 4. 失败处理和调度

每个模型调用处理一页。全站视觉调用并发默认为 1，页图渲染并发为 1。按任务轮转调度，每个任务连续完成最多 5 页就让出机会，避免一本几千页教材长期挡住短任务；不要按数据库任务排序一直跑完第一本。

网络超时、连接中断、429、临时 5xx 使用退避与抖动，最多自动重试 3 次；优先遵守上游 `Retry-After`，等待通过持久的 `next_attempt_at` 调度，不能阻塞唯一工作线程。解析 JSON 失败或正文截断至多额外重试一次，仍失败就标记待处理。

401 / 403、模型不支持图片、余额不足等错误暂停整个任务，提示修复配置；不能逐页重复发送几千次必然失败的调用。连续 5 页模型输出失败同样暂停供检查。单页损坏或渲染失败记录该页，允许继续其他页，不覆盖已存在正文。

用户停止后不再领取新页，上游取消尽力执行；停止后迟到的结果不得改变采用状态。删除资料与任务调度通过租约 / 事务协调：先停止任务并确认无活动写入，再沿用现有论文与 Wiki 引用保护和文件清理，不允许工作线程在删除后写回页面图片。

## 5. 费用和处理范围

开始整本解析前给出三种清晰选择：

1. 仅普通文字提取：不调用模型，适合文字层清晰的文档。
2. 全部所选页使用 AI：满足用户明确要求，逐页转录，不暗中跳过看似正常的页。
3. 仅处理用户选中的问题页：首期手动选择，后期可根据文字稀少、乱码、多栏等特征给出候选页，用户能修改名单。启发式检测不得宣称准确识别所有复杂页。

试读后展示实际页均耗时、调用次数，以及服务商提供的输入 / 输出 token 用量。只有配置了适用的服务商单价且返回可解释用量时才估算金额；否则显示页数 / 调用量，金额标为未知，不把图像费用简单当作固定文本 token。

支持任务级“最多处理多少页”和“最多调用次数”；支持金额预算时也必须说明是尽力限制：发起下一页前检查已知消耗和预留额度，不在额度不足时开始新页。上游不返回费用 / token 用量时暂停金额自动控制，要求改用明确的页数 / 调用预算。失败重试计入调用次数；已产生的调用费用不会因停止任务撤销。

整本模式的默认页数预算为选定总页数；试读阶段到 5 页暂停，选择直接解析整份时跳过试读暂停。管理员可配置全站额度，成员只能使用更低限额；预算耗尽必须持久暂停，服务重启不能解除。

## 6. 当前服务器的资源设计

以下数值是建议初始配置，需要压测后决定是否可正式支持；不表示已经验证 10,000 页文档。

| 项目 | 初始设计 |
| --- | --- |
| 文件大小 | 维持 250 MiB；单次上传块 8 MiB |
| 长文档页数 | 首期目标 10,000 页，上限可配置；超过时明确拒绝 |
| 模型及渲染并发 | 各 1，全站任务公平轮转 |
| 任务额度 | 全站 12 个活动文档任务；每成员最多 2 个 |
| 调度时间片 | 最多 5 页，或中途暂停 / 失败让出 |
| 图片 | 单页渲染、按需缓存；缓存全站 512 MiB，LRU 清理 |
| 核对列表 | 每次返回 50 个页面摘要，正文单页读取 |
| 正常轮询 | 5 秒仅查询摘要；后台标签降低频率 |
| 剩余磁盘保护 | 低于 2 GiB 时暂停创建和继续渲染，已完成正文保留 |

不能将每页 JPEG 永久保留：即使平均每页 500 KiB，10,000 页约需 4.8 GiB，多个历史任务会迅速放大。缓存过期后可以从原 PDF 按需重新渲染，只产生本地处理开销，不再次调用模型；活动模型请求和已打开的预览需要缓存引用保护。

图片进程加超时、地址空间 / 内存和输出尺寸约束。独立解析工作服务作为后续运行形态，资源预算与 HTTP 服务隔离；全站并发不能因网页点击次数增加。正式资源上限以包含 Poppler 子进程的压测峰值决定，触限时暂停或失败当前页，不影响 HTTP 服务。沿用现有 650 MiB 受限构建与测试脚本，严禁并行构建。

### 必须同步改造普通解析、阅读和检索

目前普通解析整份收集正文、限制 40 MiB 和 15,000 片段；AI 模块也有 2,000 页校验。扩大页数需要：

- 先 `pdfinfo` 建立真实页数及页索引，普通正文改为后台分页提取，按页事务入库；上传返回后台任务后网页轮询状态。
- 逐页限制输出长度、解析时间、进程内存与磁盘用量，任务累计资源超过管理员额度时可暂停。不能先把整本文字读入内存后再检查大小。
- 阅读页目录和正文按页 / 窗口加载，不能一次渲染几千页的全部片段。
- 采用接口按页或小批提交，不为全书构建一个巨大事务。
- 检索评估当前 BM25 对全库取数的开销，改为数据库候选召回后排序，例如经过中文分词验证的 FTS 索引；验证前不能仅抬高 15,000 片段上限就宣称支持长文档。
- 导出改为按页流式写出或后台文件任务，避免一次返回所有历史草稿。

普通页提取、AI 任务和来源状态分别保存；AI 只等其对应页的普通提取结束，不强制等完整本普通处理完成。采用后的页面不得被迟到的普通解析覆盖。

## 7. API 和兼容迁移

保留现有 `/api/sources/:id/ai-parse` 创建入口，增加 `scope: all | ranges | sample`、`ranges`、预算及试读策略。旧版 `firstPage/lastPage` 请求继续映射到范围任务，旧客户端不能修改新客户端已保存的其他选项。

新增任务操作 `pause / resume / retry-failed / stop`，返回明确的新状态与修订号。任务摘要、页码列表、单页结果、草稿保存和采用分成独立接口；旧 GET 可在兼容期对小任务返回原格式，长任务明确要求分页接口。继续使用同源校验、成员认证和编辑权限。

数据库在当前模式 4 基础上迁移。先完整备份；为旧成功页面补结果和采用标记，保留原 job ID、chunk ID、原文引用和活动正文。旧失败任务的已完成页可导入续跑任务，但历史任务默认不自动恢复，避免升级后突然调用模型。只有新版本创建且明确运行的任务可在重启后自动续跑。

创建整本任务时模型配置快照固定；更换服务商后，由用户选择“使用新配置重试未完成页”创建关联续跑段，展示哪些页来自不同模型，不隐藏混合结果来源。

## 8. 分阶段交付及验收

### 第一阶段：一次启动与可靠续跑

交付统一范围选择、整本任务、试读、逐页持久化、暂停 / 继续 / 失败页重试、任务摘要分页和分批核对。先在当前 2,000 页边界以内验证长任务机制，页面明确标出当前边界。上传入口与阅读入口都能创建同类任务；原 250 MiB 分块上传继续可用。

验收：超过 50 页的选区能够一次排队；关闭浏览器后继续；进程在页面结果提交前后被终止均能恢复；成功页不重复调度；无效凭据暂停，429 退避不堵塞其他任务；暂停和预算状态跨重启保留；取消后的迟到结果不自动采用；只读操作被拒绝。

### 第二阶段：几千页正式支持

完成普通文本分页提取、正文和目录窗口加载、检索索引、按页采用并发控制、预览缓存、后台导出，再将边界逐步扩展到目标 10,000 页。

验收使用 2,500 页及 10,000 页的可生成测试 PDF，其中包括扫描、空白、多栏和异常页面；模型部分用本地模拟器验证调度，不声称真实模型转录质量。测量整个服务及 Poppler 子进程 RSS、数据库增长、预览磁盘量、轮询大小、交互延迟和整本任务恢复时间。验收阈值应写入测试报告，未达标继续保留较低上限。

### 第三阶段：节省调用与更好核对

增加问题页候选识别、章节范围选择、预算估算和跨任务质量提示。章标题页码来自 PDF 大纲时明确来源；大纲不可靠时保留手动物理页范围。用户仍可明确选择全部页面使用 AI。

所有阶段都需要验证历史证据不变、不同页面并发采用、空白页保护、资料删除与工作线程竞争、结果分页不会覆盖编辑草稿，以及 Cloudflare 代理下上传和轮询可用。真实模型评估使用用户明确选择的试读页；开发验收不调用正式模型或消耗用户额度。

## 9. 一次整本任务示例

以一本 2,500 页教材为例，用户上传后只选一次“整份 PDF”。默认先解析 5 页；检查效果后点“继续剩余页面”，服务器按单页执行，其余文档也可轮转处理。用户在已完成 100 页时就能核对并采用前两组，其余页面继续排队。第 913 页发生临时失败只重试该页；服务在第 1,201 页重启后从未落盘页继续，已核对 / 已采用结果保持不变。用户可随时暂停，恢复时不必重新输入页码。

这是后续完善后的目标流程；当前实现范围见文档开头说明。
