# 个人学习与知识管理系统

> 初版需求保留为设计背景。2026-11-13 的 v0.3 已采用 C++20 后端与 React 网页，并实现四级团队权限、成员协作、论文对比工作流和可追溯 Wiki 页面。Wiki 的关联、版本、质量检查与检索设计见 docs/wiki-design.md。当前功能边界、运行方法和验收以 README 与 docs/verification.md 为准。

## 1. 产品目标

围绕需要学习或已经学过的书籍、课程和实践资料，建立一个能够查证来源、串联知识、辅助练习并记录学习进展的个人知识系统。

希望形成这样的使用过程：

**收集资料 → 制定学习目标 → 理解知识点 → 练习与应用 → 记录反馈 → 复习 → 更新掌握情况。**

第一阶段以个人学习助手为主。论文、项目、故障和团队资料沿用同一套资料与知识管理能力，再补充各自的字段和工作流程。

### 已确定的交付形式：网页应用

- 最终产品通过浏览器访问，所有日常操作都在网页中完成。
- 资料上传、阅读、搜索、问答、笔记编辑、知识点管理、学习计划、练习、复习和设置都提供网页入口。
- 上传资料支持网页文件选择和拖放；资料导入、解析和知识点生成显示处理状态、失败原因与重试入口。
- 阅读资料和查看问答引用都在网页内完成，支持跳转到对应页码或来源片段。
- 创建、编辑和保存操作提供明确反馈；刷新或重新打开网页后，已保存的资料与学习记录仍可恢复。
- 模型与资料处理由后台服务执行，用户通过网页发起操作、查看结果和调整可配置项，日常使用无需终端或手工编辑配置文件。
- 交付形式已经确定；本机访问、局域网访问或互联网访问属于后续部署选择。

## 2. 五类使用场景

| 方向 | 主要资料 | 希望支持的任务 | 需要保留的信息 |
| --- | --- | --- | --- |
| 个人学习助手 | 教材、课程笔记、习题 | 解释概念、串联知识点、安排学习与复习 | 章节、先修知识、学习目标、作答记录 |
| 论文研究库 | 论文、实验记录 | 比较方法、整理结论、追踪证据 | 研究问题、方法、实验条件、结论及局限 |
| 项目知识库 | 代码说明、设计文档、开发记录 | 理解模块关系、追溯设计决策 | 项目、模块、依赖、决策背景、适用版本 |
| 故障经验库 | 报错、日志、解决过程 | 查找类似故障、复用排查过程 | 环境、症状、假设、排查步骤、验证结果 |
| 团队业务百科 | 产品说明、操作流程、常见问题 | 查询流程、辅助新人学习 | 适用角色、维护人、生效时间、资料可见范围 |

这些方向作为资料用途和工作空间组织，不要求每份资料只能属于一个方向。例如，一次项目故障可以同时关联项目模块和正在学习的知识点。

## 3. 核心信息对象

### 资料与来源片段

- 资料保存书名或标题、作者、版本、文件或链接、目录、导入时间。
- 来源片段保存可引用的内容，以及页码、章节或其他定位信息。
- 一份资料可以关联多个知识点；一个知识点也可以引用多份资料。
- 保留原始资料，以便核对提取和生成的内容。

### 知识点

- 每个知识点包含名称、定义、适用条件、例子、常见误区和来源依据。
- 知识点之间可以建立“先修”“组成”“对比”“应用”等关系。
- 不同来源的表述、结论或适用条件存在差异时，分别保留并说明。
- 自动生成的内容先作为草稿，确认后再作为个人知识笔记保存。

### 技能

- 技能描述一项可以通过行动验证的能力，例如“独立实现二分查找并解释边界处理”。
- 每项技能关联必要知识点、练习任务、完成标准和实践成果。
- 同一项技能可以通过习题、实验、项目或故障排查积累证据。

### 学习记录

- 分别记录阅读进度和能力掌握情况。
- 阅读进度可标记为“计划学习、正在阅读、已读完”。
- 掌握情况可标记为“未评估、理解中、可独立完成、需复习”，并附依据和记录时间。
- 掌握情况的依据可以是本人自评、具体作答、实践成果或反馈，展示时说明依据类型。
- 每次练习保存题目、回答、反馈和涉及的知识点，支持之后回看。

## 4. 个人学习的主要流程

### 导入与整理

1. 在网页选择或拖放一本书或一份学习资料，填写基本信息。
2. 查看提取的目录和正文，确认内容可读、位置可定位。
3. 按章节生成知识点草稿，核对后保存。
4. 为知识点补充自己的解释、例子和问题。

### 制定学习路径

1. 输入学习目标、当前基础和可投入时间。
2. 选择关联资料和目标技能。
3. 根据知识点的先修关系提出学习顺序，允许手动调整。
4. 为各阶段指定阅读内容、练习和可检查的完成标准。

### 带来源的问答

1. 选择查询范围，例如一本书、一个主题或整个个人知识库。
2. 查询相关来源片段，结合问题生成回答。
3. 回答引用实际使用的片段，支持打开对应的原文位置。
4. 对推断或额外补充作出标记；资料不足时说明缺少什么依据。
5. 可以把有用的回答编辑后保存为关联笔记。

### 练习与复习

1. 针对学习目标和薄弱知识点创建练习。
2. 保存作答与反馈，关联知识点和技能。
3. 根据自评、练习表现和时间记录提出复习建议，允许调整。
4. 完成复习后记录结果，更新掌握情况的依据。

## 5. 第一版功能范围

建议先用一到三本实际要学的书验证完整学习过程。

| 功能 | 第一版范围 | 完成标准 |
| --- | --- | --- |
| 资料管理 | 优先支持带文字层的 PDF 和 Markdown；记录书籍与章节信息 | 能导入、查看正文并定位来源 |
| 知识点管理 | 自动提出草稿，支持手动新增、编辑、合并与关联来源 | 知识点能追溯原文，修改后仍可保存 |
| 资料问答 | 在选定资料范围内提问，返回可核对的引用 | 能打开所引用片段，缺少依据时有明确说明 |
| 学习进度 | 记录章节阅读进度和知识点掌握情况 | 阅读记录与掌握记录分别展示 |
| 练习记录 | 创建练习，保存作答和反馈，关联知识点 | 能查看一次完整练习及其反馈依据 |
| 复习清单 | 手动指定复习时间，并根据学习记录提出建议 | 能查看待复习内容并记录复习结果 |

扫描件识别、音视频、多人成员管理、自动跟踪代码仓库和复杂实验数据分析放入后续阶段。

## 6. 网页页面与交互

建议以左侧导航切换主要功能，在页面顶部提供搜索和资料上传入口。页面布局以电脑浏览器为优先，窄屏下仍可完成主要操作。

| 页面 | 展示内容 | 网页内可执行的操作 |
| --- | --- | --- |
| 学习首页 | 当前目标、阅读进度、待复习内容、最近练习 | 继续学习、开始复习、创建目标 |
| 资料库 | 书籍与其他资料、分类、学习状态、处理状态 | 上传、搜索、筛选、编辑资料信息、失败重试 |
| 资料详情 | 目录、原文、关联知识点、学习笔记 | 阅读与翻页、定位章节、添加笔记、生成并确认知识点、针对资料提问 |
| 知识点与技能 | 定义、来源、先修关系、关联技能、练习历史 | 新增、编辑、合并知识点，关联技能，记录掌握情况 |
| 学习计划 | 目标、阶段、关联章节、练习、完成标准 | 创建计划、调整学习顺序、更新完成情况 |
| 问答页 | 对话记录、资料范围、回答、来源片段 | 选择资料、提问、追问、打开引用、将回答编辑保存为笔记 |
| 练习与复习 | 待完成任务、题目、作答、反馈、历史记录 | 开始练习、提交答案、查看反馈、记录复习结果、调整复习时间 |
| 设置 | 模型连接、资料处理与数据管理选项 | 修改配置、检查连接、导出资料与学习记录 |

资料详情建议采用“目录 / 原文 / 学习侧栏”布局；学习侧栏切换笔记、知识点和问答。问答引用在原文阅读区域打开，并保留当前问题和阅读上下文。

上传与生成任务进行时可以继续浏览其他页面，返回后查看任务进度和结果。空资料库、无搜索结果、处理失败、模型未配置和保存失败都需要提供说明及对应操作入口。

第一版先用列表和详情页展示知识关系；后续根据实际使用需要增加图谱视图。

## 7. 端到端验收示例

以学习一本算法教材为例，以下操作全部通过浏览器完成：

1. 在网页上传教材，查看处理进度，完成后打开某章并核对正文与页码。
2. 保存“二分查找”的知识点，关联原文和先修知识。
3. 提问“循环边界为什么这样设置”，得到能定位到依据的回答。
4. 完成一道相关习题，保存代码或回答以及反馈。
5. 将该练习关联到“独立实现二分查找”的技能，并记录评估依据。
6. 设置复习时间，之后可以重新作答并查看两次表现。
7. 刷新或重新打开网页，仍可找回原始资料、知识点、引用和全部学习记录。
8. 在设置页完成模型连接配置和连接检查，并将学习记录导出到本机。

验收时同时检查：没有相关资料的问题、两个来源意见不一致的问题、资料提取失败和保存失败的情况，以及这些状态下的网页反馈与恢复操作。

## 8. 后续扩展顺序

1. **个人学习**：完成资料、知识点、问答、练习和复习流程。
2. **实践沉淀**：接入项目记录和故障案例，让技能关联实际成果。
3. **研究整理（v0.2 已实现）**：论文元信息、对比矩阵、原文证据、审核发布、历史恢复与报告导出。
4. **团队共享（v0.2 已实现）**：一个部署对应一个共享团队，独立账号和四级角色，评论、任务分配、版本冲突检查；按文档授权和多个隔离工作区仍属于后续范围。

## 9. 开发前需要确认的选择

- 优先服务的学习领域和第一批真实资料。
- 网页第一版部署在本机、局域网，还是可从外部访问的服务器。
- 对本地或云端模型、运行成本和资料存储位置的偏好。
- 自用优先还是第一版就需要多设备或多人使用。

当前实现与验证记录见 README、docs/deployment.md 和 docs/verification.md。
