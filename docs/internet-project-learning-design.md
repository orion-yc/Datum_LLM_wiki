# 互联网项目学习空间

状态：公开 GitHub 项目学习已实现第一版。日期：2026-11-18。

第一版支持导入公开仓库、目录或单个文件，生成基于实际文件的学习路线，在应用内查看带行号的源码和提交历史。读者可按路线记进度和笔记，编辑者可将源码关联至现有 Wiki 或知识点；配置模型后可生成带证据的导读和回答。更新由用户触发，未变的文本按 Git blob 复用，历史证据保留。当前使用文件名与文本检索，尚无符号级调用图、自动建立先修关系、其他网站或私有仓库导入；下文保留完整设计方向。

## 目标与范围

用户粘贴 GitHub 仓库或其中一个目录的链接后，建立一个可持续学习的项目空间：了解项目用途和结构、阅读有出处的源码解释、按目标完成学习路线、把知识点与已有知识串联，并在项目更新后增量维护。

第一版聚焦公开 GitHub 仓库；后续扩展官方文档、技术文章和其他代码托管平台。“互联网学习”是导航入口，“项目学习空间”是每个仓库的学习载体。普通网页是资料来源，仓库是有结构、有版本的资料集合，两者不应强行使用同一套无结构导入界面。

“学习所有东西”对应完整的文件清单、清晰的内容覆盖和逐步深入能力，不承诺首次请求就由模型读懂整个仓库。不默认递归抓取外链、安装依赖或执行项目代码。

## 创建空间：从一个链接开始

首屏只需要粘贴链接，可选填写一句目标，比如“学会这个项目的网络通信设计”。

识别仓库、分支或标签、链接范围。仓库链接默认索引当前默认分支；文件 / 目录链接只导入该范围，页面明确提醒当前范围，用户可改为整个仓库。导入记录固定到具体 commit，不能把不同时间获取的文件拼成没有版本的来源。

先在后台发现结构，再给出预览：语言、文档入口、源码目录、测试目录、文件数、预计体积、忽略项和预计模型分析范围。用户可以先打开项目空间，在后台继续建立索引，不必等整本项目全部分析完。

导入和模型分析分开：文件发现、下载、文本提取不调用模型；生成导读、学习路线和解释才消耗模型调用。无模型时仍能浏览结构、搜索、阅读、记笔记和手动建立知识关系。

## 项目空间的六个视图

| 视图 | 用户得到什么 |
| --- | --- |
| 项目概览 | 用途、运行方式说明、主要模块、阅读入口、版本和覆盖进度 |
| 学习路线 | 可编辑的阶段、对应知识、必读代码、检查问题和实践任务 |
| 源码阅读 | 文件树、代码、符号 / 章节导航、解释和笔记、来源行号 |
| 知识网络 | 概念、模块、文件和实践之间可解释的关系 |
| 项目问答 | 限定当前版本与范围的回答，每个关键结论可返回源码或文档 |
| 学习记录 | 阅读位置、笔记、练习、自评、任务进度、更新影响 |

界面以概览、路线和阅读为主，不默认打开一张密集大图。知识网络先展示当前模块的一跳关系，可筛选展开；表格 / 列表提供同等能力，便于手机和键盘使用。

项目概览和架构说明会标注生成依据：README 明示、代码静态分析、模型推断、用户核对。模型推断不能冒充真实运行验证。

## 学习路线如何生成

提供三个预设目标：快速上手、理解架构、深入实现。可补充关注点和已有基础，允许跳过已掌握的知识。

以学习一个服务端项目为例：

1. 理解项目解决的问题：读 README、示例与配置说明，解释输入输出。
2. 找到程序入口与主流程：读入口文件和主要模块，画出一次请求的路径。
3. 学习核心机制：逐个理解路由、鉴权、数据访问、并发等实际存在的模块。
4. 阅读测试理解约束：查看正常路径、异常输入和边界条件。
5. 完成一个小改动：例如增加参数校验，指出修改位置和需要验证的行为。
6. 回顾与迁移：解释设计取舍，将同类知识关联到其他项目。

每一步包含学习目标、先修知识、具体文件 / 符号 / 行号、解释草稿、两三个检查问题和一个可选实践。路线根据实际仓库调整，项目不存在的模块不能硬凑。学习步骤可以立即使用草稿；转为团队正式 Wiki 的内容仍遵循现有核对发布流程。

“已读”“已自评理解”“已完成实践”分别记录；打开文件、看过解释或模型回答正确都不自动等于掌握。

## 把知识点串起来

分为两个相互连接的层次：

- 项目结构：入口、模块、文件、符号，以及导入 / 调用 / 数据流关系。
- 学习知识：概念、方法、先修、实例、练习，与既有知识库关联。

例如“请求鉴权”知识页引用项目的鉴权函数和权限测试；它的先修知识是 HTTP 与会话，后续是接口权限设计。同一知识页还可以引用另一个项目的不同实现，用来比较取舍。

| 关系 | 示例 | 生成与核对方式 |
| --- | --- | --- |
| 包含 | 项目 → 鉴权模块 → 文件 | 目录结构与明确规则 |
| 导入 / 引用 | 文件 A → 文件 B | 对支持的语言进行静态提取，注明解析能力 |
| 调用 | 路由处理函数 → 权限函数 | 有代码位置和解析证据；无法解析的动态调用保留未知 |
| 先修 | HTTP → 会话 → 鉴权 | 可编辑的学习关系，不从 import 关系直接推断 |
| 实现 / 实例 | 鉴权概念 → 某个函数 | 有源码证据的候选关联，用户可确认 |
| 对比 | 两个项目的鉴权方式 | 保留双方版本与证据 |
| 应用 | 权限知识 → 增加权限测试 | 与现有实践任务和学习计划关联 |

模型只能提出关系草稿，不能靠同名自动合并概念。与已有知识连接时显示候选、理由和引用，让用户选择关联 / 新建 / 合并。先修关系检查循环；源码调用关系可以有环，不能使用同一条约束。

## “全项目学习”的处理方式

对所有发现文件保留清单与状态，包括未下载、已获取、已索引、已生成解释、失败及忽略原因。界面区分文件索引覆盖与模型解读覆盖，不能用一个“100%”混淆。

默认优先 README、docs、示例、配置和依赖清单、程序入口、主要源码、测试。默认不送模型分析二进制、生成文件、构建产物、依赖副本和大体积数据；忽略项保持可见，用户可以调整。依赖清单可以建立索引和链接，不等于导入全部第三方依赖源码。

先按文件发现结构，再按模块生成摘要，最后组织项目导读。用户点到某个函数、问题或知识点时，再检索关联内容深入解释；请求不能把整个仓库一次塞给模型。支持的语言可按语法结构切片，不支持时回退为带行号文本，不能伪称已建立准确调用图。

每条重要说明保存仓库、commit、路径、行号 / 符号和引用片段。可在应用内打开版本快照，或跳到对应 GitHub 版本；项目更新后原学习记录的证据仍可定位。

## 增量更新与不重复分析

项目空间绑定明确来源范围，先采用手动“检查更新”；后续再考虑定时同步。固定 tag / commit 的空间不静默追随主分支。

文件按内容指纹和解析器版本缓存；重命名且内容不变时复用内容索引并更新路径。新增和修改的文件只重建受影响片段；未变文件和解释继续复用。模型解释缓存还要包含证据指纹、模型和提示词版本，避免把新模型配置与旧结果混为一谈；用户可明确选择复用或重新分析。

同步生成新快照，准备完成后用户切换。更新列表显示修改的模块、可能需要重读的路线步骤、需要复核的知识关系。被删除文件标为历史来源，不删除已有笔记或证据，不把旧路线进度全部归零。

任务支持暂停、继续、失败项重试和重启恢复。内容获取与模型分析进度分别展示；已完成项目不能因刷新浏览器重新调用模型。

## 与当前系统衔接

新增的对象是项目空间、版本快照、文件 / 符号索引、分析任务和有类型的证据关系。不要把仓库伪装成一份巨大的 TXT 或一个 PDF 来源。

复用现有 Wiki 的草稿 / 引用 / 发布 / 历史，现有知识点的先修与熟练度，学习计划 / 练习以及讨论和任务。已有 PDF 知识也能与代码证据关联，但需要扩展来源引用类型，不能用 PDF 页码字段硬塞源码行号。

检索支持当前项目 / 模块、当前版本及全知识库三个范围；项目问答默认当前快照。提示关联知识可以来自其他项目，引用仍标明来源，避免把另一个版本的行为当成当前代码事实。

现有检索会扫描本地片段。开放大型仓库前，需要先验证分范围候选检索与索引，不能把全仓库所有代码混入现有检索后宣称性能不变。

## 服务资源和获取边界

当前服务器内存约 1.6 GiB，采用有上限的后台获取、分页文件清单和串行模型分析。仓库内容由服务器获取，不经过用户浏览器上传；实际 GitHub 到服务器的可达性和速度需开发时测试，不能预先保证比当前文件上传更快。

当前允许一次提交整个仓库，后台对同一提交逐文件保存进度。保护值为 20,000 个清单文件、256 MiB 候选文本总量、单文件 2 MiB；超过单文件限制的文件仍在清单内显示跳过原因。单次模型分析先覆盖核心文档和入口，用户可继续分析模块。

不执行导入项目的安装、构建、测试或脚本。仓库文本作为待学习资料，不作为应用的执行指令。只允许已支持的托管来源，下载跳转和外链逐次验证，不访问内网地址；不自动跟随子模块、Git LFS 内容或文档外链。展示 README 内的远程图片和 HTML 时需做内容隔离。

公开仓库先行，私有仓库后续使用服务端加密凭据和明确的团队授权；不能假设持有某人令牌就有权向整个团队公开其私有代码。保留原文件许可证和来源，生成内容不宣称改变原许可证。

## 交付顺序

第一阶段完成公开 GitHub 项目导入、版本快照、文件树与来源阅读、项目导读、学习路线、带引用问答，以及手动将项目知识关联到现有 Wiki / 知识点。它必须形成“导入 → 学一节 → 找到原代码 → 关联知识 → 练习与记录”的完整流程。

第二阶段增加按类型展示的知识关系、先修路线引导、跨项目关联和增量更新影响提示。第一阶段保留关系数据，第二阶段再做完整网络视图，避免先做图形演示却没有可追溯的内容。

第三阶段扩展官方文档与文章、语言语法索引、更多来源和私有仓库；真实执行代码的沙箱练习作为独立能力设计。

验收重点：输入同一版本两次不重复处理；暂停 / 重启保留进度；未覆盖文件明确可见；答案和关系均能返回准确版本及代码位置；更新后历史笔记仍有效；重复概念不自动合并；低内存环境导入与检索响应可控；未运行任何仓库脚本。
